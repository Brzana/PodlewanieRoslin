# AGENTS.md

## Layout

Monorepo, three independent toolchains — each folder builds separately; never
cross-edit between them.

- `firmware/` — ESP32 plant-watering controller (PlatformIO, Arduino framework, C++)
- `android/` — Android client (Kotlin, Jetpack Compose, single Gradle module)
- `ios/` — iOS client (Swift, SwiftUI)
- `docs/ble-protocol.md` — single source of truth for the BLE contract:
  service/characteristic UUIDs and command/response framing. A protocol change
  must update firmware + Android + iOS in the same change — nothing fails at
  compile time, only at runtime.
- `docs/wiring.md` — ESP32 pin map, power wiring, and pin constraints for the
  watering hardware.

## Commands

### firmware/ (run in `firmware/`)
- Build: `pio run`
- Flash to device: `pio run -t upload`
- Serial monitor: `pio device monitor` (115200 baud)
- Dependencies and board config live in `platformio.ini` — add libraries via
  `lib_deps` there, never globally.

### android/ (run in `android/`)
- Build: `./gradlew assembleDebug` (on Windows: `gradlew.bat`)
- Unit tests: `./gradlew testDebugUnitTest` — single test:
  `./gradlew testDebugUnitTest --tests "com.podlewanieroslinek.app.SomeTest"`
- Instrumented tests need a device/emulator: `./gradlew connectedAndroidTest`
- Requires JDK 17 (AGP 8.x). Versions (AGP/Kotlin) are pinned in the root
  `build.gradle.kts`.

### ios/ (run in `ios/`, needs macOS)
- The `.xcodeproj` is generated by XcodeGen and **gitignored** — after cloning,
  or after editing `project.yml` / adding files, run `xcodegen generate`.
  Never edit the project file by hand.
- Build: `xcodebuild -project PodlewanieRoslinek.xcodeproj -scheme PodlewanieRoslinek
  -destination 'generic/platform=iOS Simulator' build`

## Gotchas

- BLE is a runtime permission, not a manifest-only one:
  - Android 12+: `BLUETOOTH_SCAN` + `BLUETOOTH_CONNECT` must be requested at
    runtime or scans return nothing.
  - iOS: `NSBluetoothAlwaysUsageDescription` is set via `project.yml`
    (`INFOPLIST_KEY_NSBluetoothAlwaysUsageDescription`) — regenerate the
    project after changing it.
  - "BLE connection doesn't work" reports are usually a missing permission,
    not a protocol bug.
- Device name and UUIDs in firmware (`firmware/include/ble_protocol.h`) must
  match what the apps scan for — check `docs/ble-protocol.md` before assuming
  the firmware is broken.
- Pin assignments in `firmware/include/pins.h` must match `docs/wiring.md` —
  update both in the same change. When choosing new pins: GPIO 6–11 are wired
  to internal flash (never usable), GPIO 34/35/36/39 are input-only, and
  analog sensors must go on ADC1 (GPIO 32–39) — ADC2 reads fail while the
  WiFi/BLE radio is on.
