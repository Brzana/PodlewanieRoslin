# AGENTS.md

## Layout

Single-hardware monorepo. The hardware described in
`docs/hardware_documentation.md` (Polish) is the **single source of truth** —
in any conflict between docs or code, that file wins.

- `firmware/` — Arduino Mega 2560 plant-watering controller (PlatformIO,
  Arduino framework, C++). Local LCD 1602 I2C + KY-040 encoder UI,
  soil-moisture sensor, float switch, relay-driven 12 V membrane pump, plus
  an HM-10 / AT-09 BLE–UART bridge on `Serial1` (pins 18/19) for the phone
  apps. USB `Serial` stays for flashing + Serial Monitor.
- `android/` — **active.** BLE client for the HM-10 (service `0xFFE0`, char
  `0xFFE1`, JSON lines chunked to 20 B — see `docs/ble-protocol.md`). Stack:
  Kotlin, Jetpack Compose, built-in `android.bluetooth` APIs, single Gradle
  module.
- `ios/` — **active.** Same BLE contract via CoreBluetooth
  (`BlePumpController.swift` + `ContentView.swift`). Needs a real device —
  the Simulator has no BLE radio.
- `docs/hardware_documentation.md` — **source of truth** for hardware: BOM,
  Arduino Mega pinout, 12 V / 5 V power distribution, sensor characteristics,
  and the base hardware-test sketch. Update it first; all files below follow
  it.
- `docs/wiring.md` — quick-reference pin map and power summary **derived from**
  `docs/hardware_documentation.md`. A pin change must update the source-of-truth
  doc, this file, and `firmware/include/pins.h` in the same change.
- `docs/ble-protocol.md` — **active phone contract:** fixed HM-10 UUIDs
  (`0xFFE0`/`0xFFE1`), JSON lines (`water` / `stop` / `status`), status/error
  objects, and the **20 B write rule**. Firmware `src/main.cpp`, `android/`
  and `ios/` must stay in sync with it — nothing fails at compile time, only
  on the radio.
- `docs/usb-protocol.md` — cable fallback (flash / Serial Monitor / OTG):
  same line format, shared firmware parser. Phone apps normally use BLE.
- `docs/requirements.md` — **class acceptance criteria (mandatory):**
  direct AVR register use in firmware critical paths (encoder ISR via `PINE`,
  float via `PINE`, relay via `PORTH`) + **zero `delay()` calls** (non-blocking
  `millis()`/timer timing only). Firmware `src/main.cpp`, `include/config.h`
  and `include/pins.h` must stay in sync with it.

## Commands

### firmware/ (run in `firmware/`)

- Build: `pio run`
- Flash to device: `pio run -t upload`
- Serial monitor: `pio device monitor` (115200 baud)
- Board target is Arduino Mega 2560 (`board = megaatmega2560`) in
  `[env:megaatmega2560]`. Dependencies and board config live in
  `platformio.ini` — add libraries via `lib_deps` there, never globally.
  Current libs: LCD driver (`LiquidCrystal_I2C`, I2C address `0x27`, fallback
  `0x3F` — see `firmware/include/config.h`).
- Code map: `include/pins.h` = Mega pinout (sync with both docs),
  `include/config.h` = calibration + timing constants, `src/main.cpp` =
  hardware-verification skeleton (encoder interrupts, soil mapping, float
  interlock via `setPump()`, non-blocking LCD/Serial). Next steps are marked
  as TODOs in `main.cpp` (menu → auto mode → EEPROM settings).

### android/ (active — BLE to the HM-10, run in `android/`)

- Build: `./gradlew assembleDebug` (on Windows: `gradlew.bat`)
- Unit tests: `./gradlew testDebugUnitTest`
- Requires JDK 17 (AGP 8.x). No radio library — plain `android.bluetooth`
  APIs (`BlePumpController.kt` + `MainActivity.kt`).
- BLE is a runtime permission, not a manifest-only one: Android 12+ needs
  `BLUETOOTH_SCAN` + `BLUETOOTH_CONNECT` granted in-app (the app asks on
  start); on SDK ≤ 30 a BLE scan additionally needs location. Test on a real
  device — the emulator has no real radio.
- Phone-side copy of `docs/ble-protocol.md` lives in `BlePumpController.kt`:
  keep UUIDs (`0xFFE0`/`0xFFE1`), command JSON and the `{`-line parsing rule
  in sync with firmware.

### ios/ (active — BLE to the HM-10, run in `ios/`, needs macOS)

- The `.xcodeproj` is generated by XcodeGen and **gitignored** — after cloning,
  or after editing `project.yml` / adding files, run `xcodegen generate`.
  Never edit the project file by hand.
- Build: `xcodebuild -project PodlewanieRoslinek.xcodeproj -scheme PodlewanieRoslinek
  -destination 'generic/platform=iOS' build` (use a real device for BLE;
  `iOS Simulator` builds but cannot scan).
- `NSBluetoothAlwaysUsageDescription` is set via `project.yml` — regenerate
  the project after changing it.
- Phone-side copy of `docs/ble-protocol.md` lives in `BlePumpController.swift`:
  same sync rule as Android.

## Gotchas (Arduino Mega 2560 — from the source-of-truth doc)

- **Pins 0 (RX0) / 1 (TX0) stay free** — they carry USB upload + Serial Monitor.
  Never assign peripherals to them.
- **I2C is fixed:** LCD 1602 I2C uses **pin 20 (SDA) + pin 21 (SCL)**.
  Address `0x27` (try `0x3F` if dead); contrast via the blue pot on the I2C
  backpack.
- **Encoder KY-040:** `CLK` → pin **2** (`INT4`), `DT` → pin **3** (`INT5`),
  `SW` (button) → pin **4**. All `INPUT_PULLUP`, button active `LOW`.
  Use hardware interrupts on 2/3 so steps are not lost.
- **Float switch ZP5210:** pin **5**, `INPUT_PULLUP`, second wire to `GND`.
  `LOW` = float up = **water present**; `HIGH` = float down = **tank empty**
  (if inverted after mounting, flip in code or rotate the float 180° after
  removing the lower cotter pin). Firmware must **block the relay and abort an
  ongoing watering** when the tank is empty — membrane pump must not run dry
  for more than a few seconds, and it must never be submerged (only the suction
  hose goes into the tank).
- **Relay (JQC3F-5VDC-C):** `IN` → pin **7**, `OUTPUT`, typically active `LOW`
  (`LOW` = pump runs, `HIGH` = pump off). Define `RELAY_ON` / `RELAY_OFF`
  constants. Power side switches **+12 V**: module `DC-IN/OUT (+)` → relay
  `COM`, relay `NO` → pump `+` (red dot), module `DC-IN/OUT (-)` → pump `-`
  directly; `NC` stays empty.
- **Soil sensor (LM393 + fork probe):** only `AO` is used → pin **A0**
  (10-bit ADC, 0–1023), `DO` unused. Characteristic is **inverted**: dry/air ≈
  950–1023, wet/water ≈ 300–450. Map with
  `map(val, 1023, 300, 0, 100)` + `constrain(…, 0, 100)` after calibrating in
  the target pot. Resistive probe drifts over time (electrolysis) — expect
  recalibration. Buzzer pin **11** is reserved (not mounted).
- **Power (no breadboard — the blue supply module with `S1` / `DC-IN` is the
  hub):** 12 V rail (`DC-IN/OUT`) feeds Mega `VIN` + `GND` and the pump circuit
  above; 5 V rail (`5V OUT`) feeds LCD `VCC`, encoder `+`, soil `VCC`, relay
  `VCC`, and `GND` for all of them (+ one float wire). Mega pin `5V` is
  **not** tied to the module's `5V OUT`, so USB + 12 V barrel can be connected
  at the same time.
- **Timing:** pump run-time and soak pauses must use non-blocking timing
  (`millis()` / AVR timers), never `delay()` — blocking freezes the encoder
  and LCD.
- **Class rules (see `docs/requirements.md` — mandatory):**
  1. **Direct registers in critical paths** — encoder ISR reads `DT` (PE5) via
     `PINE`, float (PE3) via `PINE`, relay (PH4) via `PORTH`, each with a
     register+bit comment. `pins.h` pin numbers are guarded by
     `static_assert`s in `main.cpp`; a pin move must update both.
  2. **No `delay()` anywhere** in `firmware/` (`grep -rn "delay("
     firmware/src firmware/include` must be empty apart from names like
     `pumpDeadline`). Boot splash, LCD/Serial refresh, and pump timing all use
     `millis()` intervals (`SPLASH_MS`, `STATUS_UPDATE_MS`, `SERIAL_UPDATE_MS`,
     `pumpDeadline`).
- **Phone link is BLE via HM-10 (`Serial1`), USB is the fallback:** apps talk
  GATT (`0xFFE0`/`0xFFE1`, 20 B chunks, reassemble to `\n`); the cable
  (`Serial`, OTG) shares the same line format with Serial Monitor. Machine
  lines start with `{`, human debug with `#`; apps ignore non-`{` lines.
- **HM-10 wiring is level-shifted one way:** Mega `TX1` (pin 18, 5 V) →
  module `RXD` **via voltage divider**; module `TXD` → Mega `RX1` (pin 19)
  direct. `BT_BAUD` (9600) must match the module (`AT+BAUD`); the name the
  apps look for is set via `AT+NAME=RoslinkiPump`. UUIDs are fixed by the
  module firmware — never invent custom ones unless the bridge is replaced.
- **One outstanding GATT op (Android):** `BlePumpController` serialises
  notify-enable + chunk writes through a single queue — do not fire parallel
  `writeCharacteristic` calls or chunks get dropped.
- Old ESP32 rules (GPIO 6–11 flash, ADC2 vs ADC1, strapping pins, 3.3 V logic,
  BLE runtime permissions, advertised name/UUID sync) do **not** apply to this
  hardware. Ignore them unless the hardware doc changes.
